# 欠席連絡・振替授業 計画（案）

送迎予約（docs/pickup-plan.md）を仕上げてから着手する。生徒名簿・LINE の本人確認・管理者の承認・通知の仕組みは送迎予約のものを使う。

## 流れ
```
生徒：授業を休む連絡 ──→ 振替ストック +1（自動）
生徒：ほかの学年の授業日を選んで振替申請 ──→ ストックを1つ押さえる（申請中）
管理者：承認 ──→ 振替授業に出席できる（ストックは使用済み） / 却下 ──→ ストックは戻る
```
- 休む授業：自分の学年の、公開済みの授業（`events.type = '<学年>授業'`）
- 振替先：ほかの学年の授業日
- 休む日に送迎予約があれば「送迎も取り消しますか？」と聞く。振替の日は送迎予約もできる

## 画面
- 生徒：`pickup.html` を生徒用ページに統合し、タブ「送迎」「欠席・振替」（LINE のメニューの入口を1つにする）
  - 欠席の連絡、振替ストック（残り・期限）、振替の申請と状態
- 管理画面：タブ「欠席・振替」
  - 承認待ち（振替申請の承認・却下）／日ごと（授業ごとの欠席者・振替で来る生徒）／生徒ごと（ストック残り・履歴・手動の増減）
  - 欠席の連絡・振替の申請も、送迎と同じアラームで通知

## データ
| テーブル | 中身 |
|---|---|
| `class_absences` | 欠席の連絡（生徒・授業・理由・受付日時） |
| `makeup_credits` | 振替ストック1つ＝1行（元の欠席・期限・状態：使える／申請中／使用済み／期限切れ） |
| `makeup_requests` | 振替の申請（ストック・振替先の授業・状態：申請中／承認／却下／取り消し） |

- 生徒はテーブルに直接触れない。期限・定員・ストックの二重使用は DB 関数で確認する
- CSV の「すべて削除して置き換える」で `events` の id が変わるので、欠席・振替には授業の日付・種別・時刻も写して保存する（`event_id` は `on delete set null`）

## 未決定（着手前に確認）
1. 欠席連絡の期限（案：授業開始まで。過ぎた連絡・無断欠席はストックなし）
2. ストックの有効期限（案：欠席日から3か月、または年度末）
3. 同じ学年のほかの曜日も振替先にできるか
4. 1回の授業に受け入れる振替の人数
5. 振替申請・取り消しの期限
6. 承認された振替を休んだときの扱い、出欠をつける機能の要否
7. 休講（塾の都合）にストックを付けるか（案：付けない。必要なら管理者が手動で追加）

## 進め方
A. DB（テーブル・RLS・DB関数・テスト） → B. 生徒の画面 → C. 管理画面と通知 → D. 「予定」タブへの件数表示（管理画面のみ） → E. LINE 通知・バックアップ（送迎のフェーズ6・7と一緒に）

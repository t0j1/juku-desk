# 定時印刷：日次出席名簿・単語テスト（仕様ドラフト）

状態：ドラフト（実装は承認後）。Tojiro さんのサンプル未着のため、項目・出題条件は「案」と「未決」を分け、数値は決め打ちしない。

## 1. 背景と現状

- 定例印刷（`PrintSchedule`）は固定 PDF のみ。毎日 18:00 に `PrintScheduleJob` が翌日分の `PrintJob`（pending）を作る。
- 名簿・単語テストは、印刷時点のデータから PDF を作る必要がある（固定 PDF では足りない）。

## 2. データの参照元

| 帳票 | 参照するテーブル | 使う項目 |
|---|---|---|
| 日次出席名簿 | `students` / `student_weekdays` | `name`, `grade`, `enrolled_on`, `left_on`, `weekday`（通う曜日） |
| 単語テスト | `wordbooks` / `words` | `wordbooks.name`, `words.number`, `term`, `meaning` |
| （出題の記録・案） | `tests` / `test_items` | 既存の小テスト用。単語テストの記録に流用するかは未決 |

`quizzes` テーブルは無い（schema.rb）。

## 3. 生成のタイミング

現行（前日 18:00 に翌日分を作る）だと、18:00 以降〜当日の入退塾・曜日変更が名簿に反映されない。

- 案A（推奨）：ジョブは今までどおり前日に作る（印刷予定は見える）が、PDF は貸し出し（lease）の直前にサーバーで作る。当日の最新データが載る。
- 案B：ジョブの作成自体を印刷の N 分前にする（N は未決）。ジョブ作成が遅れると印刷が遅れる。
- 案C：前日に作った PDF を、当日の印刷の N 分前に作り直す。案A より仕組みが増える。

いずれも、生成に失敗したときは古い PDF で刷らず、ジョブを failed にして理由を残す（誤った名簿を刷らない）。未決：失敗時に管理画面へ通知するか。

## 4. レイアウト案

### 日次出席名簿
- 案1：1 日 1 枚の縦リスト。氏名・学年・出欠記入欄（○/×）・備考欄。
- 案2：時間割（コマ）ごとの表。氏名を行、コマを列にして出席を記入。
- 未決：コマの区切りと時刻、並び順（学年順／五十音順）、1 枚に載せる人数の上限。

### 単語テスト
- 案1：左に問題（英語）、右に解答欄の 2 列。解答は別ページ。
- 案2：問題と解答欄を 1 枚にまとめ、解答は別ファイル。
- 未決：問題数、出題範囲（番号の範囲／前回の続き／ランダム）、出題方向（英→日／日→英）、生徒ごとに変えるか、名前欄。

## 5. 受入基準（テスト可能な形）

1. 名簿：対象日の曜日に通う在籍生（`enrolled_on <= 日付` かつ `left_on` が空または日付以降）だけが載る。退塾済み・未入塾は載らない。
2. 名簿：当日の朝に退塾日を入れた生徒が、印刷時の PDF に載らない（案A/C の確認）。
3. 単語テスト：指定の単語帳の、指定範囲の単語だけが出る。範囲外・他の単語帳は出ない。
4. 同じ日付・同じ雛形で 2 回生成しても、ジョブは 1 件（既存の `print_schedule_id` と `scheduled_for` の一意性を維持）。
5. 無効の雛形・失効したステーションでは作らない（現行の挙動を維持）。
6. 生成失敗時はジョブが failed になり、理由が `result_message` に残る。古い PDF は刷らない。
7. 日本語が文字化けせず、1 枚に収まらない場合は複数ページになる（人数が多い名簿）。
8. 1 日の上限（`PRINT_SCHEDULE_DAILY_LIMIT`）が、新しい種別にも効く。

## 6. 非ゴール

- 出席の電子記録・集計（紙に記入するまで）。
- 生徒ごとの成績管理・自動採点。
- 印刷後の紙のスキャン取り込み。
- 雛形の種別追加以外の、印刷エージェント側の変更。

## 7. 未決事項（Tojiro さんのサンプル待ち）

名簿の項目と並び順、コマの有無、単語テストの問題数・範囲・方向、解答の扱い、失敗時の通知、案A〜C の選択。

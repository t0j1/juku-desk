- 状態：design 仕上げ・UI承認（2026-10-06）。数値は「既定案（画面で調整可）」、Tojiro さん確認待ちは**要確認**と明記。
- 対象：juku-desk 管理画面「定例印刷」（`admin/print_schedules`）。
- 正本UI：`workspace/juku-nippo-ui-spec-v1.7.md` §3（トークン）／§6-5（1日のスケジュールと定時実行タスク）。

## 0. 何を変えるか

- 現状：雛形＝固定 PDF のアップロードのみ。`PrintSchedule` は `pdf_data`／`r2_key`・`sha256`・`byte_size` が必須。
- 変更：**「固定 PDF をアップロードする」に加え、雛形（種別）を選び、データソースを指定する**方式にする。
- 種別＝固定PDF／日次出席名簿／単語テスト。生成帳票は**レイアウト調整パラメータ**で調整できる。
- 既定値は推奨案。管理者が画面で変えられるので、**数値を今 決め打ちしなくてよい**（Tojiro さんのサンプル待ちの間も実装を止めない）。
- 生成のタイミングは**案A（貸し出し直前に生成）**を推奨（§5）。当日の入退塾・曜日変更が反映される。

## 1. 用語

| 用語 | 意味 |
|---|---|
| 雛形（テンプレート） | 出力する帳票の種類（固定PDF／日次出席名簿／単語テスト） |
| データソース | 帳票に載せるデータの出所（アップロードPDF／students・student_weekdays／wordbooks・words） |
| レイアウト調整パラメータ | 用紙・余白・文字サイズ・段組み・罫線など、刷り上がりの調整値 |
| 定例印刷（PrintSchedule） | 曜日と時刻を決め、毎日 18:00 に翌日分の `PrintJob` を pending で作る仕組み |

## 2. 雛形の種別（kind）

| kind | 名称 | データソース | PDF の持ち方 | 記号 |
|---|---|---|---|---|
| `fixed_pdf` | 固定 PDF | アップロードした PDF | 登録時に保存（従来どおり） | ▤ |
| `roster` | 日次出席名簿 | `students` / `student_weekdays` | 実行時に生成 | ☰ |
| `word_test` | 単語テスト | `wordbooks` / `words` | 実行時に生成 | A |

- 既定は `fixed_pdf`（既存の雛形はそのまま動く）。
- 種別は登録後に**変更可**（固定PDF→名簿 など）。変更時は不要になった PDF（`r2_key`）を解放する。

## 3. 登録・編集画面

### 3-1 全体

- 1 枚のカードに上から積む（現行 `_fields.html.erb` を拡張）。primary ボタンは「登録する」1 つだけ。
- 文字・入力欄・ボタンは v1.7 §3 の確定値（本文18／ラベル18/700／入力19・高さ52／ボタン19・高さ52／最小16px）。
- 上から：①名前 → ②雛形（種別）→ ③データソース指定 → ④レイアウト調整 → ⑤印刷設定（ステーション／曜日／時刻／部数／部単位／ホチキス／driver_preset）→ ⑥有効 → 登録。

### 3-2 雛形（種別）の選択

- 3 枚の**ラジオカード**を横並び（1200px 未満は縦積み）。
- 1 枚の中身：アイコン（24、線画）＋名称（19/700）＋説明（16／`--sub`、1行）。
- 選択中＝2px `--accent-strong` 枠＋`--inset` の背景。未選択＝`--raise-sm` の浮き出し。**色だけで示さず**、選択中は「✓」の記号＋文字をカード右上に出す。
- `role="radiogroup"`。Tab で 3 枚を順に移動、Space/Enter で選択。
- 説明文：
  - 固定PDF：「用意した PDF をそのまま刷ります」
  - 日次出席名簿：「その日に通う生徒の名簿を作って刷ります」
  - 単語テスト：「単語帳の範囲から問題を作って刷ります」

### 3-3 データソース指定（種別で切り替え）

**(a) 固定PDF**
- PDF ファイル（30MB まで、`application/pdf`）。**編集時も差し替え可**にする（現状は削除→再登録のみ。§11）。

**(b) 日次出席名簿**
| 項目 | 入力 | 既定案 |
|---|---|---|
| 対象 | ラジオ：全員（在籍中×その曜日）／学年でしぼる／特定の生徒 | 全員 |
| 学年 | 複数選択（「学年でしぼる」のときだけ表示） | 未選択 |
| 特定の生徒 | 複数選択（「特定の生徒」のときだけ表示、氏名で検索） | 未選択 |
| 並び順 | プルダウン：学年→五十音／五十音／学年のみ | 学年→五十音 |
| 出欠記入欄 | チェック（○/× を手書きする欄） | オン |
| 備考欄 | チェック | オン |

- 0 名のとき：保存はできる。実行時に 0 名なら**印刷せず**、履歴に「対象0名でスキップ」と残す（§5）。

**(c) 単語テスト**
| 項目 | 入力 | 既定案 |
|---|---|---|
| 単語帳 | プルダウン（`Wordbook`） | 未選択（必須） |
| 範囲 | 開始No.（数値）＋単語数（プルダウン 50/100/200/300/500/自分で入力）。§6-3 と同じ入力・同じエラー | 開始1・100語 |
| 出題方向 | ラジオ：英→日／日→英 | 英→日 |
| 問題数 | ラジオ：範囲から抽選（数値入力）／範囲すべて | 範囲すべて |
| 解答 | ラジオ：別紙／同じ紙の下部／なし | 別紙 |

### 3-4 レイアウト調整

- 折りたたみ（アコーディオン）「レイアウトを調整」。既定は閉じた状態で、要約（例「A4 縦・余白15mm・本文11pt」）を1行表示。
- 中身は §6 のパラメータ。各項目は入力欄（数値・プルダウン・チェック）で、右に既定値への「既定に戻す」。
- 右上に「プレビュー」。押すと**サンプルデータ**（実在の生徒名は使わない。例「生徒A／生徒B」）で1枚をその場に表示。本番データは使わない。

### 3-5 印刷設定（共通）

- ステーション（有効なもの）、曜日、時刻、部数、部単位（collate）、ホチキス、driver_preset、有効。
- **部数モード**：固定／出席名簿から自動。§6-5 と共通仕様。名簿種別のときだけ「自動」を選べる。自動＝対象人数×1人あたり部数。作成時でなく**実行時に確定**。
- 現行の文言「毎日 18:00 に翌日分を作ります」は維持。

## 4. 一覧画面

- 列：名前／雛形／データソース／ステーション／曜日・時刻／部数／状態／次回の印刷／操作。
- 「雛形」列は**記号＋文字**のピル（§2 の記号）。「データソース」列は1行要約（例「在籍×火・全員」「LEAP No.308–407・英→日」「手作りPDF.pdf」）。
- 操作は現行どおり 編集／停止・再開／削除。

## 5. PDF 生成フロー

**案A（推奨）**：ジョブは従来どおり前日 18:00 に作る（印刷予定は見える）。PDF は**貸し出し（lease）の直前に**サーバーで作る。当日の最新データが載る。

- 固定PDF：登録時に保存した PDF（`pdf_data`／`r2_key`）をそのまま使う（従来どおり）。
- 名簿／単語テスト：`PrintJob` の作成時点では PDF を持たない。`PrintJob.lease_next_for!` の直前に生成する。
  - 生成：Prawn → `Tempfile` → `PrintJob.create_with_pdf!(path:)`。**大きな String に載せない**（PR #35 の教訓）。
  - 生成に失敗したとき／対象 0 名のとき：古い PDF で刷らず、ジョブを `failed`（理由を `result_message` に残す）または `skipped` として履歴に内訳を残す。
  - メモリ：20 問の小テストで 400MB 以下（既存 AC2 を踏襲。`script/pdf_memory_probe.rb` の方式で計測し PR に数値）。
- 案B（ジョブ作成を印刷 N 分前にする）・案C（前日 PDF を N 分前に作り直す）は代替案として残す。**どの案にするかはエンジニア判断**（§13）。

## 7. データソース具体例

### 7-1 日次出席名簿

- 例：対象日 2026-10-06（火）。`enrolled_on <= 2026-10-06` かつ（`left_on` が空 または `left_on >= 2026-10-06`）かつ `student_weekdays.weekday = 2` の生徒。
- 出力：学年見出し → 氏名 → 出欠欄（○/×）→ 備考欄。
- **制限**：juku-desk に欠席・振替の記録が無い（`students` は name/grade/enrolled_on/left_on/note、`student_weekdays` のみ）。よって「出席名簿」＝**その日に通う予定の生徒**。当日の欠席・振替を反映するには出欠記録の追加が必要（未決・エンジニア判断）。

### 7-2 単語テスト

- 例：単語帳「LEAP」No.308〜407（100語）から 30 問、英→日、解答は別紙。
- 出力：左に問題（英語）・右に解答欄の 2 列。解答は別ページ。
- 出題は `wordbooks` / `words` から。抽選のロジックは既存 `Quiz`（重複なし抽選・`words_in_range`）を再利用する。

### 7-3 固定 PDF

- 例：既存の手作り PDF（`pdf_data`／`r2_key`）をそのまま刷る。レイアウト調整は適用しない。

## 8. データモデル（案）

`print_schedules` に追加（マイグレーション）：

| 列 | 型 | 既定 | 備考 |
|---|---|---|---|
| `kind` | string, not null | `"fixed_pdf"` | 既存行は既定で従来動作 |
| `source_config` | jsonb, not null | `{}` | 種別ごとのデータソース設定（学年・単語帳・範囲など） |
| `layout_config` | jsonb, not null | `{}` | §6 のレイアウト調整値（未指定は既定案で補完） |
| `copies_mode` | string, not null | `"fixed"` | `fixed`／`roster_auto`（§6-5 と共通） |

- `sha256` / `byte_size` を **null 許可**に変更（名簿・単語テストは登録時に PDF を持たないため）。既存行は値があるので安全。
- 種別ごとのバリデーション：`fixed_pdf` は PDF 必須、`roster`・`word_test` は `source_config` の必須キーを検証。
- `print_jobs` は変更なし（生成時に PDF が入る）。

## 10. 受入基準

元ドラフト（PR #103）の 1〜8 を維持し、次を追加する。

1. 名簿：対象日の曜日に通う在籍生だけが載る（退塾済み・未入塾は載らない）。
2. 名簿：当日の朝に退塾日を入れた生徒が、印刷時の PDF に載らない（案A/C の確認）。
3. 単語テスト：指定の単語帳の、指定範囲の単語だけが出る。
4. 同じ日付・同じ雛形で 2 回生成してもジョブは 1 件（`print_schedule_id`×`scheduled_for` の一意性維持）。
5. 無効の雛形・失効したステーションでは作らない（現行維持）。
6. 生成失敗時はジョブが failed になり、理由が `result_message` に残る。古い PDF は刷らない。
7. 日本語が文字化けせず、1 枚に収まらない場合は複数ページになる。
8. 1 日の上限（`PRINT_SCHEDULE_DAILY_LIMIT`）が新しい種別にも効く。
9. 種別を選ぶと、対応するデータソース欄だけが表示される（他種別の欄は非表示）。
10. レイアウト調整を変えると、プレビューと実際の PDF に反映される。未指定は既定案になる。
11. 既存の固定PDF雛形は、種別 `fixed_pdf` として従来どおり動く（データ移行なし）。
12. 名簿の対象が 0 名のとき、印刷せず履歴に「対象0名でスキップ」と残る（成功と見せない）。
13. 画面は 1440px で横スクロールが出ない。1200px 未満で種別カード・2カラムが縦積みになる。文字は16px未満にしない。
14. 種別・状態は記号＋文字で示す（色だけにしない）。

## 11. 移行パス

- 既存の雛形は `kind="fixed_pdf"` の既定値でそのまま動く（**データ移行なし**）。
- 編集画面で固定 PDF も**差し替え可**に変更（現状は削除→再登録のみ）。
- ロールバック：`kind` 列を無視すれば従来動作に戻る。生成器は種別 `fixed_pdf` では呼ばれない。

## 12. 非ゴール

- 出席の電子記録・集計（紙に記入するまで）。
- 生徒ごとの成績管理・自動採点。
- 印刷後の紙のスキャン取り込み。
- 印刷エージェント側の変更（雛形の種別追加以外）。
- 帳票の自由レイアウト編集（WYSIWYG）。パラメータで調整できる範囲に留める。
